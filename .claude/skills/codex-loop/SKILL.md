# Codex 교차 검토 루프

> **사용 중지 (2026-11-10 사용자 지시).** OpenAI 크레딧이 없어 Codex 검토를 하지 않는다. 아래 내용은 다시 켤 때를 위한 기록이다.

사용자의 지시를 Claude가 초안으로 만들고, Codex가 정정·누락·구체화·바리에이션을 검토하고, Claude가 그 의견을 종합해 완성한다.

## 언제 쓰나

- **쓴다:** 결과물이 남는 작업. 코드 구현과 수정, 문서·보고서·기획서, 화면 디자인, 데이터 분석, 설정 변경.
- **건너뛴다:** 단순 질문 답변, 오타나 한 줄 수정, 사용자가 "코덱스 없이", "검토 없이"라고 말한 경우.
- 사용자가 "코덱스로 검토해서" 같이 명시하면 작은 일에도 쓴다.

## 순서

### 1단계. 초안 만들기 (Claude)
1. 작업폴더를 만든다: `.codex-loop/<YYYYMMDD-HHMM>-<짧은-주제>/` (git에 올라가지 않는다).
2. `request.md`에 사용자의 지시를 **원문 그대로** 적는다. 참고한 파일, 제약(DESIGN.md 등)도 덧붙인다.
3. 평소처럼 작업해 초안을 만든다. 파일을 바꾸는 작업이면 실제로 바꾼다.
4. `draft.md`에 초안을 적는다.
   - 문서·기획·답변이면 초안 본문 전체.
   - 코드 작업이면 무엇을 왜 바꿨는지, 바꾼 파일 목록, 확인한 것과 못 한 것. Codex가 저장소 파일을 직접 읽을 수 있으니 코드를 통째로 붙이지 않아도 된다.

### 2단계. Codex 검토
```bash
scripts/codex-review.sh .codex-loop/<작업폴더> 1
```
- 결과는 `<작업폴더>/review-1.md`. 몇 분 걸릴 수 있으니 timeout을 넉넉히(최대 600000ms) 준다.
- Codex는 읽기 전용(`-s read-only`)으로 돌아서 파일을 고치지 않는다.
- 코드 변경이 크면 추가로 플러그인의 `/codex:adversarial-review`를 써도 된다. 사용자가 직접 실행하는 명령이라, 필요하면 사용자에게 권한다.

### 3단계. 종합 개선 (Claude)
1. `review-1.md`의 항목을 하나씩 판단한다. Codex 의견이라고 무조건 따르지 않는다. 직접 파일을 확인해 사실인지 검증한다.
2. 받아들인 의견을 반영해 결과물을 고친다. 바리에이션 중 더 나은 것이 있으면 채택하거나 사용자에게 선택지로 제시한다.
3. "반드시 반영할 것"이 많았거나 구조가 크게 바뀌었으면 `draft.md`를 갱신하고 2단계를 한 번 더 한다(`... 2`). **최대 2라운드.**

### 4단계. 보고
사용자에게 결과물과 함께 아래를 짧게 보고한다.
- Codex 검토로 바뀐 점 (반영한 항목)
- 반영하지 않은 의견과 그 이유
- 사용자가 고를 수 있는 바리에이션이 있으면 그 선택지

## Codex를 못 쓸 때

`review-N.md`가 `CODEX_UNAVAILABLE` 또는 `CODEX_FAILED`로 시작하면:
- 작업을 멈추지 않는다. 같은 5개 관점(정정/누락/구체화/바리에이션/우선순위)으로 **Claude가 스스로 검토**한 뒤 3단계를 한다.
- 보고할 때 "Codex 검토 실패: <이유>"를 반드시 적는다. 검토받은 척하지 않는다.
- 흔한 원인: OpenAI 계정 크레딧 소진(`Quota exceeded`), codex CLI 미설치(세션 시작 훅이 설치함).
